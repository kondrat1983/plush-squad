# v1.0 · Toys go on an adventure (#47)

A toy the kid removes from My Squad packs a backpack and goes exploring instead of being deleted. It sends postcards, and it can come home any time, with a souvenir after a long trip. Written by `game-designer` on 10 Oct 2026, from the code on `origin/main` (v0.9.0, commit a8e0d30).

Rules this doc keeps: no shop, no ads; no FOMO timers, no punishing waits; online stays friends-only; a grown-up can still really delete a photo.

## 1. Pitch
"Remove" becomes "Go explore!". Your toy visits a world you have opened, sends up to 3 funny postcards from the rivals there, and comes back when you call it, with a souvenir if it stayed 3 days or more. A 10-year-old cares because nothing is lost (he can clean up his squad without guilt) and postcards from Sasquatch are funny. A 6-year-old cares because "my teddy is on holiday" is much nicer than "deleted".

## 3. Content
### Flow
1. Details panel: the REMOVE button becomes **ADVENTURE** (icon `j:ticket`, same size and place as B50 / #48).
2. Card: "**Send Teddy on an adventure?**" / "Teddy packs a snack and goes exploring. Teddy will send you postcards!" Buttons **STAY** (star) and **GO EXPLORE!** (coral).
3. Card: "**Where to?**" One button per opened world (`worldOpen(w)`), with the world icon (`moon`, `rocket`, `mapleleaf`, `pumpkin`) and a **SURPRISE ME** button. Spooky only while `EVENT_ON`.
4. Short goodbye: the toy cut-out hops off the panel to the right (`whoosh`), toast "Teddy is off to CANADA!". Back to My Squad.

### My Squad
- A new card after NEW TOY: **ADVENTURES** with `j:ticket` and a count chip ("3"). Shown only when at least one toy is away. A small dot when a postcard is unread or a trip is done.
- Tap → Adventures list (same paging as My Squad, B05): each away toy with its picture, the world icon, "Day 2 in Canada", its postcards (tap to read again), and two buttons: **CALL HOME** and a small **SAY GOODBYE** (see 4.3).

### Postcards

## 4. Signature rule: away, never gone
### 4.1 Coming home
- **CALL HOME** works any time. No waiting is ever required.
- Away **3 or more calendar days** (all 3 postcards sent): "Teddy is home with a souvenir!" The toy gets the world souvenir (a small world icon on its card, `t.souv`), +1 capsule the first time this toy brings a souvenir from this world, and toy XP +20 if toy growth ships.
- Away less than 3 days: "Teddy is home! Next time stay longer for a souvenir." Nothing lost.
- Squad full (14): "Your squad is full! Send another toy exploring first." The button stays, nothing breaks.
- The toy comes back with all its fields (name, type, XP, badges). It is not made the hero automatically.

### 4.2 Limits
| Limit | Value | Why |
|---|---|---|
| Toys away at once | 20 [?] | IndexedDB space (a cut-out data URL is about 100-500 KB [?]) and a list that pages well |
| Postcards per trip | 3 | no nagging |
| Souvenir capsules | 1 per toy per world, ever | no "send and return" farming; max today 14 toys × 4 worlds |
| Adventure bus full | "The adventure bus is full! Call a toy home first." | |

The hero can go too: the hero falls back to Jack, as today.

### 4.3 Real delete (grown-ups)
**SAY GOODBYE** (small, cream, in the Adventures list only) opens the parent gate (multiplication table, owner's rule). Then: "Delete Teddy's photo for good?" YES / NO. YES removes the toy from `away`, `IDB.del`, the cloud row (next push) and **the PNG in the storage bucket** (`sb.storage.from('toys').remove([uid + '/' + id + '.png'])`; the "delete own" storage policy already exists). Needed for privacy: a photo can show a room or a face.

### 4.4 EASY / NORMAL / HARD
Same on every difficulty.

## 5. Save, IndexedDB and cloud
### Save (no migration needed)
```
Save.data.away = [ { toy: { ...the toy record... }, trip: { world: 'canada', left: '2026-10-10', cards: 1, seen: 1 } } ]
toy.souv = ['canada']   // on the toy record, souvenirs it brought home
```
- A separate array, so everything that reads `Save.data.toys` stays right: squad grid, hero lookup, `Net.summary`, "Squad Goals" (5 toys; an earned sticker stays earned).
- World stored as a key (`hills`, `space`, `canada`, `spooky`), not an index: `WORLDS[3]` exists only during the event.
- `left` uses `todayKey()` (local date). Clock moved back: postcards wait until the date passes `left` again.

### IndexedDB
The picture **stays** in IDB while the toy is away. Boot loads textures only for `Save.data.toys`; the Adventures list and postcards load `toy_<id>` from IDB when they open (as Boot does).

### Cloud (no schema change)
Recommended option A:
- `pushNow()`: the keep set is `toys ∪ away`, so away rows are not deleted.
- The row's `meta` gets `away: 'canada'` (update own toys: RLS policy "update own toys" exists). Cleared on return.
- `Net.squad()` and `Net.museum()` skip rows with `meta.away`, so friends do not see or duel an away toy. Likes are kept for when it comes back.
- `applyCloud()` downloads pictures for `toys ∪ away`, so a toy sent away on the iPad can come home on the iPhone.
- Cost: museum RPC still returns away rows (limit 80), filtered on the device [?]. Old cached clients would show away toys until they update.

Option B (rejected): let `pushNow()` delete the row and re-upload on return. Breaks return on a second device (no IDB picture there) unless it relies on the orphaned bucket file.

## 6. Rewards and progression
| Reward | When |
|---|---|
| Postcards (3 per trip) | days 1-3 after leaving |
| World souvenir icon on the toy | home after 3+ days |
| +1 capsule | first souvenir per toy per world |
| Toy XP +20 | home after 3+ days (with toy growth) |
| Sticker **Explorer** ("A toy came home with a souvenir", icon `j:ticket`, title "Explorer") | first souvenir; +1 capsule like every sticker (`checkAch`) |

No XP for the player (it would make leaving toys away a grind).

## 8. Acceptance criteria and test ideas (for `qa-tester`)
1. Details of a toy shows ADVENTURE (not REMOVE), ≥ 90 px tall, on D1-D5; Jack has no ADVENTURE button.
2. GO EXPLORE! → world picker shows only opened worlds (+ Spooky only with `?halloween` or in season) and SURPRISE ME.
3. After sending: toy gone from the grid, `Save.data.away` has it, `IDB.get(id)` still returns the picture, hero is Jack if it was the hero.
4. ADVENTURES card appears only with ≥ 1 away toy; count chip right; paging works with 20 away toys on D1 and D5.
5. Postcards: set `trip.left` to 1, 2, 3, 5 days ago → the first map open shows one toast with the right count, the cards have the right world text; no 4th postcard; no toast on the second map open the same day; streak popup (if shipped) comes first.
6. CALL HOME after < 3 days: toy back in the grid, no capsule, no souvenir. After ≥ 3 days: souvenir icon, +1 capsule once; a second trip to the same world gives the souvenir line but no capsule.
7. CALL HOME with 14 toys: friendly message, nothing lost.
8. 21st toy cannot be sent; message shown.
9. SAY GOODBYE: parent gate; wrong answer does nothing; right answer removes from `away` and IDB; with a test account (mocked Supabase) the row delete and the storage `remove` call are made.
10. Cloud (mocked): push keeps away rows, sets `meta.away`; `Net.squad()` / museum skip them; `applyCloud()` fetches pictures for away toys.
11. Rotation on the Where-to card, the Adventures list and an open postcard: comes back on the same screen, nothing sent twice.
12. Bedtime / daily limit: Adventures list blocked like My Squad; postcards wait (days still count).
13. Regression: toy duel, friend duel, campaign and Kraken result tests (CLAUDE.md rule) with a toy hero, and a toy duel after a toy came home.
14. Sticker Explorer granted once, with its capsule.
