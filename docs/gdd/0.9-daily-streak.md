# v0.9 · Pillow Week: daily streak with a Sleepy Pillow (#32)

A gentle 7-day track that replaces the daily capsule gift. GDD §17 "Daily streak". Written by `game-designer` on 5 Oct 2026, from the code on `origin/main` (v0.8.2, commit 03d7236).

Rules this doc keeps (GDD §2, §15, decisions.md): no shop, no ads, nothing to buy; no FOMO timers, no punishing streak loss; bedtime and daily limit apply; online stays optional.

## 1. Pitch
Play on any 7 days and fill a row of 7 pillows: capsules and XP every day, a GOLDEN capsule on day 7. Missed a day? The Sleepy Pillow naps for you and keeps your place. Miss more, and a new week just starts, with no sad screen. A 10-year-old cares because the golden capsule is today only from the online Kraken, and filling a row is satisfying; a 6-year-old never feels punished.

## 4. Signature rule: the Sleepy Pillow
### What counts as a day played
- A day is a **local calendar date** on the device, as `YYYY-MM-DD` (`todayKey()` in `js/extra.js`).
- A day counts the first time the **map opens** that day, the same moment as today's daily gift. No duel is needed. Reason: the bar stays low for a 6-year-old, and there is one daily moment, not two.
- It does **not** count while bedtime or the daily limit is active (`PSExtra.blockedReason()` is not null). The bedtime screen opens instead, and nothing is given.

### The track logic
`gap` = calendar days between the last counted day and today (1 = yesterday).
| Case | What happens | What the kid sees |
|---|---|---|
| first day ever | day 1 | today's hint "Daily gift: +1 capsule!" |
| gap = 0 | nothing (already counted) | nothing |
| gap = 1 | next day | popup "DAY n!" |
| gap = 2, Sleepy Pillow ready | pillow used, next day | popup "DAY n!" with the pillow line |
| gap = 2, pillow already used in this week | quiet restart: day 1 | only the day-1 hint, same as any normal day 1 |
| gap ≥ 3 | quiet restart: day 1 | day-1 hint |
| day 7 was reached on an earlier day | new week: day 1, pillow ready again, `weeks + 1` | day-1 hint |
| gap < 0 (clock moved back) | nothing until the date passes the last day | nothing |
| gap ≤ −2 (clock was far ahead before) | last day is quietly set to today, no reward, the day number stays | nothing |
| gap = 2 but less than 36 real hours since the last count | treated as gap = 1 (a time-zone jump east) | normal popup |

- One Sleepy Pillow per week (per 7-day track), not per calendar week. A week takes 7 played days, at most 8 calendar days.
- "After two missed days the streak restarts": that is gap ≥ 3, or a second single miss in the same week.
- A restart is never announced. Day 1 looks exactly like today's daily gift.

### EASY / NORMAL / HARD
Same track on every difficulty. A difficulty bonus would push kids to HARD only for rewards, and the duels already give HARD × 1.5 XP.

- Reward line: "+2 capsules!" / "+1 capsule +20 XP!" / "GOLDEN capsule!".
- One button: `YAY!`. When the popup closes, the capsule button wiggles (as today). If XP gives a level up, it shows on the next result panel, not here [?].

## 5. Balance
| Per week, playing every day | Today | Proposed | Change |
|---|---|---|---|
| Capsules from the daily moment | 7 | 9 | +2 |
| Golden capsules | 0 (+1 from the Kraken if online) | 1 (+1 Kraken) | +1 |
| XP | 0 | 140 | about one Canada win (Max 130, Bob 140) |
| Super rare boosters expected | 7 × 8.9% = 0.6 | 9 × 8.9% + 1 = 1.8 | +1.2 |

- XP: 140 a week is 31% of the L8 → L9 step (450). A kid who plays daily already makes several levels a week, so this does not speed up Jack's move unlocks (all by L5).
- "Too easy": boosters are optional, one per duel, and used up. One extra super rare a week (Spare Heart or Super Star) helps in 1-2 duels out of 20+. It does not change rival pep, damage or AI. The chief tester can still skip boosters on HARD. Win rates per difficulty do not change [?] (no rival numbers touched; checked `RIVALS`, `DIFFS`, `DEF_W`).
- A 6-year-old on EASY: nothing to lose, the pillow forgives a day, and a restart looks like a normal day.
- No simulation needed: the rewards are fixed, with no randomness except the normal capsule roll.

## 6. Rewards, save fields, cloud
### Save
```
Save.data.streak = {
  days: ['2026-10-05', '2026-10-06'], // counted local dates of this week, ascending, max 7
  pillow: 0,         // 1 = the Sleepy Pillow was used this week
  at: 1759650000000, // Date.now() of the last count (time-zone rule)
  weeks: 0,          // finished weeks (day 7 reached)
  seen: '2026-10-06' // last day whose popup was closed (rotation, see 7)
}
```
- `Save.data.daily` (old field, `toDateString()` format) stays written for older code and tests.
- Migration (v0.9 first load): if `daily === new Date().toDateString()` (gift already taken today), set `streak = { days: [today], pillow: 0, weeks: 0, seen: today }` with no extra reward. Otherwise create an empty streak. Nobody starts mid-week.

### Optional sticker
"Pillow Week": reach day 7 once (`streak.weeks >= 1`), icon `pillow`, title "Sleepy Champ", +1 capsule (as every sticker). Only one tier; no 30-day or 100-day stickers (they would push kids to play daily).

### Cloud save with two devices
How it works today (`js/net.js`):
- The whole save is one JSON blob, last writer wins by `savedAt`.
- At login, `reconcile()` picks the newer save, or asks the kid when the owners differ.
- On start with a kept login, `catchUp()` **only pushes** (when the local save is newer). It never pulls a newer cloud save.
- So with the iPhone and the iPad both logged in, the device that saves last overwrites the other one's progress. This is a general risk, not only for the streak (see "Mismatches"). The chief tester plays on both devices.

Proposed streak rules:
1. Merge rule wherever two saves meet (`reconcile`, and the pull below): keep the `streak` whose last day is later; if the same, keep more `days`; `weeks` = the bigger one. A merge never makes the local streak shorter.
2. Before counting a day on map open, a logged-in device fetches only the cloud streak (`saves.data->streak`, one select, 1.5 s timeout) and merges it. Offline or timeout: count locally.
3. Rewards are not merged. Capsules live in the save that wins; the same day on two devices does not give double rewards once the saves meet.

Worst case for a kid (offline on one device): the Sleepy Pillow gets used, or a quiet restart. Never a loss of anything earned.

## 7. Edge cases
| Case | Behaviour |
|---|---|
| Rotation while the popup is open | The reward is stored before the popup. The rebuilt map shows the popup again while `seen !== last day`, with no second reward and no fly-in animation. Rotation is not blocked. |
| Rotation on the map before the popup | Same: shows once the map is rebuilt. |
| Midnight during a session | Nothing mid-duel. The next map open counts the new day. |
| App opened at bedtime | `MapScene.create` checks `blockedReason()` before `dailyStreak()`. No count, no reward. (Today `dailyCapsule()` runs before the bedtime fade, see mismatches.) |
| Grown-up taps 15 MORE MINUTES / NO LIMIT TODAY | The map opens, so the day counts. |
| Daily limit reached | The day was counted earlier, at the first map open. |
| Brand-new player | Hills comic (if `0.9-world-comics.md` ships), then the map with the day-1 hint. Day 1 never shows the popup. |
| Comic due when the map opens | The comic first (it leaves `MapScene.create` early), the streak on the map after it. |
| What's new on the title | Separate screen, no overlap. |
| Sticker toasts on the map | Under the popup (depth 95 vs 96). They queue and show after `YAY!` [?] (dev to check `flushToasts` timing). |
| Time zone west (date goes back) | gap 0 or -1: nothing. |
| Time zone east (a date skipped) | gap 2 within 36 h: treated as gap 1. |
| DST change | Dates are compared as calendar dates (`Date.UTC(y, m, d)`), so a 23 h or 25 h day does not matter. |
| Kid moves the clock ahead to farm | Possible offline, low stakes (no shop). When the clock is fixed, gap ≤ −2: `last` reset to today quietly, no reward that day, no punishment. |
| Log out | The device becomes a fresh guest (today's behaviour); the streak is safe in the cloud save. |
| Weekly Kraken golden capsule | Independent. Both add to `goldCaps`. |

## Open questions

### Mismatches found (for the GDD sync; no G-ID given, `findings.md` is being edited by another agent)
- `dailyCapsule()` runs inside `MapScene.create`, before the scene `create` event, where `extra.js` checks bedtime. So the daily capsule is given even when the app opens at bedtime and goes straight to the bedtime screen. Small, but the streak must not copy it.
- Two date formats: `Save.data.daily` uses `toDateString()` ("Mon Oct 05 2026"); `extra.js` uses `todayKey()` ("2026-10-05"). The streak uses `todayKey()`.
- Cloud save: with a kept login, the app never pulls a newer cloud save on start (`catchUp()` only pushes). Two logged-in devices can overwrite each other's progress. Likely a bug worth its own issue (S2 [?], needs a `qa-tester` check), separate from this feature.
- Issue #32 title says "v0.8"; the streak is not in v0.8 (GDD §17 says "not scheduled").
